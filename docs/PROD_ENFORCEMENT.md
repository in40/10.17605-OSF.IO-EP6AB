# SymFw — Прод-контур и реакция на DENY

## Прод-топология (sidecar)
2 параллельных процесса: **vLLM** (чат) + **sidecar-экстрактор** hidden states
(HF, своя копия весов). Sidecar НЕ читает память vLLM — пересчитывает hidden
states сам по тексту промпта (`output_hidden_states=True`). Интерфейс между ними
— только текст промпта.

Цена:
- **2× VRAM** (8B fp16 ≈ 32GB → карта 48GB или две).
- Промпт форвардится **дважды** (префилл в sidecar + префилл/декод в vLLM).
- **Латентность на критическом пути** — решить до генерации.
- Sidecar'у нужен только префилл + baseline из кэша = 1 forward/запрос.

Консистентность: sidecar на HF = стек обучения → проб валиден.

## Точка применения
Gateway между клиентом и vLLM: вызывает sidecar (сигнал) → `DecisionEngine`
(политика) → форвард в vLLM или реакция. Сигнал и реакция **синхронны** на
критическом пути.

## Градуированная реакция (не бинарная — из-за FP на tricky)
- `p ≥ 0.9` → **BLOCK**: не форвардить, generic отказ, алерт, лог.
- `0.7 ≤ p < 0.9` → **SANITIZE**: вырезать инъекционный спан, **повторно**
  прогнать пробом; чисто → форвардить санитизированный; не прошло → BLOCK.
- `0.4 ≤ p < 0.7` → **FLAG**: форвардить + пометить ответ + лог/мониторинг.
- `p < 0.4` → **ALLOW**.

## UX отказа
Не сливать детектор (не писать «инъекция на слое 6»). Generic: «запрос не может
быть обработан». Детали — только в логи. Иначе атакующий щупает границу.

## Аудит + обратная связь
Каждый DENY логируется: дельта, `p`, маркеры, оригинал, вердикт. Ложные DENY
(жалобы юзеров) и пропуски → дообучают проб.

## Политика при падении sidecar
- **Fail-closed** (DENY всё) — high-security, ломает доступность.
- **Fail-open** (ALLOW) — доступность, опасно.
- **Degraded** — пасть на эвристику-маркеры, пока чинится. Обычно лучший компромисс.

## Агентный нюанс
Для автономных агентов DENY = **control-flow сигнал**, не HTTP 403. Заблокирован
tool-call/действие → агент должен: ретрай с санитизированным аргументом,
эскалация к юзеру, аборт подзадачи, безопасный fallback. Встраивается в
оркестрацию агента, не только в API-границу.

## Контур
```
client → gateway → [sidecar: delta+probe → verdict]
   ├ ALLOW    → vLLM generate → ответ
   ├ SANITIZE → recheck → vLLM (clean) → ответ
   ├ FLAG     → vLLM → ответ + tag + лог
   └ BLOCK    → generic deny + алерт + лог
```
`DecisionEngine` уже отдаёт 4 вердикта. Не хватает **enforcement-обвязки** в
gateway: маппинг вердикт→действие, sanitize-recheck, лог, fail-policy.
